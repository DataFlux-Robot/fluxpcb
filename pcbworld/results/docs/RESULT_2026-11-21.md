## 2. 改变结果的三件事

### 2.1 规则模型同余（118/118 证明）

两处独立缺陷，均属"路由器与裁判不共享同一规则表"：

1. **strip 切断项目绑定**：`pcbnew` 按 basename 绑定项目；strip 把板写成
   `placed.kicad_pcb`，板旁没有 `placed.kicad_pro`，导出器把所有网络解析到
   KiCad 默认类。首次审计：118/118 板不同余（117 每网络值错、113 缺默认
   规则、57 过孔直径错）。
2. **适配器整数量化**：整数 µm 无法表示 0.1524mm（6 mil），且文本不匹配时
   静默 no-op。

修复：项目绑定 + 精确浮点 µm + 基于 S 表达式 span 的补丁 + 补丁后重解析
并与项目表逐网络 diff。结果：**118/118 同余，0 读回失败**。

### 2.2 事务化修复

每批修复在字节级快照上执行，仅当**严重度加权违规负载严格下降**时提交
（`short 50·clearance 10·width 1·unconnected 10`），规则同余是硬前提；
否则字节级回滚。全量：**54 次 commit，0 次硬声明回归**。

执行中发现并修复的两个测量-状态错配：
- `b.Save()` 会用内存默认设置覆写板旁 `.kicad_pro` → 后续 DRC 读错规则。
  修复：`save_preserving_project()`。
- 结果行文件非原子写入，断电后变成 NUL 字节。修复：tmp + `os.replace`。

### 2.3 证据账本（可证伪门）

7/7 门通过负控制资格认证；118/118 规则同余声明通过；worst-first 合成为
104 pass / 14 fail；哈希链完整。三个注入损坏（错误项目、陈旧铺铜、
0.4µm 量化短缺）全部被拒：`inject_corruption.json` 14/14。

## 3. 剩余 14 块失败板的归因

| 类别 | 数量（按违规计数） |
|---|---|
| `unconnected` | 56 |
| `router_fault:track_width` | 55 |
| `router_fault:clearance` | 38 |
| `other:shorting_items` | 11 |

（计数为失败板上违规条目之和，非板数；板数 14。）

主要矛盾是 **Freerouting 的 75% 收窄**：它在贴焊盘的狭窄处把 254µm 压到
190.4µm，低于 DRC 下限；盲加宽在多数板上一键清零（0006、0023、0057 等），
少数板加宽会吃间距，需要**单网络重布**而不是原地加宽。

## 4. 复现

```bash
# 规则同余审计（118 板，不布线）
KICAD_PYTHON=<kicad python> python work/pcbworld/audit_rules.py

  work/pcbworld/score_results_v2.json work/pcbworld/score_final.json

python work/pcbworld/audit_ledger.py

```

## 5. 诚实边界

- 单次运行；Freerouting 的路径选择在相同输入下可复现（0006 五次重复均为
  同一结果），但不同规则表会改变路径，因此"基线 vs 新"的差异是规则导致的，
  不是噪声。
- D3-C 仍落后基线 1 块，且 D3-A/B 仍低于 PNS 执行器；差距在布线器几何能力，
  不在契约层。契约层的作用是让差距**可归因**（router_fault vs
  out_of_model），而不是假装消失。
- 未做 pass^k 重复评测（时间成本）；下一步应对 14 块失败板 ×3 次重复，
  区分确定性失败与偶发失败。
