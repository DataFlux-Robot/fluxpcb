# PCBWorld-Bench 2026-11-25 — fluxpcb vs PCBRouteAgent

这一批是 fluxpcb 的**最终确认运行**（`02a65b3` + 逐算子事务关闭 + 路由器 JVM 堆上限）。
方法、对照与边界写在包仓库：`fluxpcb/research/PCBWORLD_2026-11-25.md` 与实验记录 §6.13。

## 协议

| | PCBRouteAgent | fluxpcb |
|---|---|---|
| 论文 | arXiv:2611.08175v2，Opus 5.5，KiCad PNS + 重试 | — |
| 路由器 | KiCad 9.0.8 推挤引擎 | Freerouting 2.5.0，2 线程 15 遍上限，240 s 超时；超时后 8 线程再跑一次 |
| 修复 | LLM 智能体重试 | 规则算子 + 事务门，每板最多 3 轮 |
| 每板时间上限 | 未披露 | 900 s（+120 s 收尾） |
| 判据 | error 级 DRC 违规 + 零未连接 | 同 |
| 重复 | 每板 1 次 | 每板 3 个独立格子 |

运行环境补充：6 个工人；`FLUXPCB_JAVA_XMX=2g`。不设堆上限时六个路由器 JVM 会耗尽内存，
两块最大的板（0496/0599）会无证书消失；加上限后 357 格**零崩溃**（见包仓库实验记录 §6.12）。

合计 357 格、71 分钟：**357/357 有证书，仪器问题 0**。

## 诚实边界

- 比较不是配对检验：没有 PCBRouteAgent 逐板名单，只能比集合通过率。
- 它每板跑一次、时间上限未披露；我们每板三个独立格子，按"每次都过"报，是最严口径。
- DRC 会随机漏报（同一文件多次运行报出不同数量）；通过/不通过不受影响，
  但单次读数有 ±数处波动。
- 接入"结论带规则ID/假设、验证器干预验证"等七项做法的过程中出现过一次**更差**的全量结果
  （D3-A 99.3%、D3-B 93.3%）。原因是逐算子事务损害了小板的短路修复，已默认关闭；
  原始数据与归因留在包仓库实验记录 §6.12，没有删掉。
