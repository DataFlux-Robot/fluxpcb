## 0. 综述收敛出的单一诊断

fluxpcb 的 8 类缺陷（P1–P8）共享一个结构：

> **被测的量是状态的函数，但系统用可变的名字指称它；而判断该量的法官可被被判断者书写。**

由此产生三个静默非法操作（综述 B）：替换（读陈旧值）、非法连接（跨状态聚合，如 95.8% 与 78 opens）、默认化（缺失字段变成值再写回，如 `.kicad_pro` 被覆写）。

综述 A 的强结论：**不存在不可 hack 的代理目标**（Skalse et al., arXiv:2209.13085；有限评估均衡 arXiv:2603.28063）。因此修复方向不是"更好的指标"，而是**权限分离 + 可证伪的门 + 状态绑定**。

综述 D 的强结论：PCB 规则模型分歧全部落在 L1（阈值表）与 L3（量化）——**两者可判定**。穷举表 diff 就是证明，不需要 fuzzing 才能定案。

综述 C 的强结论：nopekit 只组合**证据状态**，不组合**动作**——它没有 action/journal/全局合取门/回滚。这四项必须由 fluxpcb 补上，且文献中**没有 PCB 修复域的端到端先例**。

## 1. Tier 1（高风险/高回报）

### T1-A 规则模型同余证书（RMCC）

- **类别**：契约/同余（P2 静默语义漂移、P8 未探测通道）
- **假设**：若路由器规则表由板子的**有效**规则经解析式变换导出，且输出与裁判规则表做穷举 L1 diff、序列化误差严格小于比较余量（L3），则剩余 DRC 违规全部是几何性（布线器故障）而非规则模型伪影——因为两张规则表在有限域上可证相等，任何违规都无法归因于错误约束。
- **依据**：综述 D §6.1/§6.2（L1/L3 可判定；我们的全部分歧都在 L1+L3）；综述 D §2.3（商业流靠共享可执行体，翻译流只靠相关性测试）。
- **预测**：PCBWorld-Bench 上 `rule_model_artifact` 违规 = 0（当前未分类）；clearance>0.2mm 且含无网络焊盘的板改善；23 块失败集 clean-pass 至少 +1。
- **指标**：(a) L1 不匹配板数 修前/修后；(b) DRV 分类（out-of-model vs router-fault）；(c) 失败集 clean-pass 增量。
- **运行估计**：审计 ~10 min（118 板 strip+parse）；23 板布线与评分 ~40 min。
- **状态**：执行中

### T1-B 认证事务修复（CTR）

- **类别**：组合/事务（P5 非交换动作、P6 知识即常量、缺失全局不变量）
- **假设**：若每批修复动作仅在**全部活跃硬声明**的合取仍成立于新状态时才提交（DRC 错误类型集不新增、错误+未连接总数严格下降、规则同余保持），并按字典序 (新增硬违规类型, 总数) 接受，则修复永远不能缩小硬声明集——因为接受定义在后状态的完整声明向量上，而非算子局部目标上。
- **依据**：综述 C §1.4/§5.6（lexicographic feasibility-first 是唯一可证防止硬换软的表述）；Necula PCC（小证书+独立检查器）；Alive2 逐次翻译验证发现 47 个 LLVM bug；Poracle 保守护条件 99% 精度。
- **预测**：修复引入的硬声明回归 = 0（当前存在：widen 晚于 waiver 会破坏自己刚写的下限）；D3-B clean-pass ≥ 90%；waiver 被后续动作违反数 = 0。
- **指标**：每板回归数、clean-pass、pass^3（固定 10 板 × 3 seed 复跑）。
- **运行估计**：失败集 30 min；全量 118 板 ~2 h。
- **状态**：执行中

### T1-C 可证伪证据账本（FGEL）

- **类别**：评估器完整性（P1 自指验证、P2 测量-状态错配）
- **假设**：若每个 pass 必须满足 (i) 门在当前版本上有**密封的 known-bad 夹具**并已证明其失败、(ii) 判决以读数集哈希 `rho` 为键、(iii) worst-first 合成且亚分辨率比较返回 `indeterminate`，则陈旧/错状态/量化损坏的测量无法被报告为 pass——因为不存在从 unqualified/stale 门到 pass 的代码路径，且比较本身在不确定带内拒绝裁决。
- **依据**：nopekit 的 qualification/rho/freshness/worst-first（综述 A §5.5、B §G）；综述 B §F.5 比较不可判定规则；综述 A §3.3 升级通道实验（23.6%→5.3%）。
- **预测**：3 个注入损坏（陈旧铺铜、错误 `.kicad_pro`、0.4µm 短缺）全部被拒绝或判 indeterminate；审计中未报告 pass = 0；完成度从标量变为 worst-first 向量。
- **指标**：检出率（要求 3/3）、false-pass 数、rho 稳定性。
- **运行估计**：~1 h（含注入夹具）。
- **状态**：执行中

## 4. 结果

### T1-A 规则模型同余证书 — 已完成（118/118 板审计）

**第一次审计（旧 harness）**：118/118 板规则表不同余。

| 分歧类别 | 板数 |
|---|---|
| `value`（每网络 width/clearance） | 117 |
| `default_rule`（pcb 级默认规则缺失） | 113 |
| `via_drill` | 113 |
| `via_diameter` | 57 |

**根因（可复现、已修复）**：`scripts/kicad_board.py:strip` 把板写成
`placed.kicad_pcb`（新 basename），板旁没有同名 `.kicad_pro`，于是
`pcbnew.LoadBoard(placed)` 不绑定项目，Specctra 导出把所有网络解析到
KiCad 默认类（0.2mm）。这是综述 D §1.1「两条独立规则通道」的实测实例：
导出器本身没有坏，是调用方切断了项目绑定。

**修复后第二次审计**：

| 指标 | 值 |
|---|---|
| 修前每网络/过孔分歧 | **0 / 118**（项目绑定修复后） |
| 修前 `default_rule` 缺失 | **118 / 118**（KiCad 导出不写 pcb 级规则） |
| 解析式补丁后完全同余 | **118 / 118** |
| 补丁自证失败 | 0 |

**结论**：T1-A 假设成立的前半部分——规则分歧可被穷举判定并完全消除。
剩余的唯一系统性缺口是无网络对象（`default_rule`），已由补丁注入。
`via_drill` 只存在于 padstack 名字中，重命名与几何必须同步重标记，
这一点在补丁里被显式处理并由读回验证。

**副产品**：修复了一个运算符缺陷——`widen_narrow_tracks` 把**同网络焊盘**
当作障碍物，导致 0023 板 5 条宽度违规全部"拒绝加宽"。修复后同一块板
5 → 0。

### T1-B 认证事务修复 — 执行中发现并修复的三个新缺陷

原计划的"事务门"本身工作正常（每条 commit/rollback 都有完整前后状态），
但执行过程中暴露了三个更深的缺陷，全部属于同一类（测量与状态错配）：

**B-1 `b.Save()` 重写板旁 `.kicad_pro`。** `evaluate()` 每次重灌铺铜后
`board.Save(path)`，pcbnew 会用内存中的默认设置覆写项目文件；随后
`kicad-cli` 在独立进程中读到的是默认规则（0.2mm），不是板子的规则。
结果是：测量对象（规则表）在测量之前就被替换了。修复：
`save_preserving_project()` 在保存前后快照/恢复项目字节，并在
`run_bench.evaluate` 中再次从源项目复制。验证：保存前后 `sha256(pro)`
相等，DRC 消息中的最小宽度回到板子的 0.2032/0.254。

**B-2 几何预检过度保守。** `widen_narrow_tracks` 用"矩形焊盘外接圆"
做碰撞预检，把 1.85×0.45mm 的焊盘当成半径 0.925mm 的圆，拒绝了 DRC
实际接受的加宽。改为精确矩形距离后，0023/0029/0030/0037/0055 的
1–2 条残差全部清零。进一步发现：即使精确几何，预检仍会拒绝 0006
的两条窄线，而**无条件加宽后 DRC 为 0**——裁判比我们的模型更权威。

**B-3 接受准则从"禁止新类型"改为"严重度加权严格下降"。**
原规则会拒绝"5 个宽度违规 → 1 个间距违规"这类净改善；但它同时也会
拒绝"2 个宽度违规 → 0"。改为
`weighted = Σ severity(type)·count + 10·unconnected`，
`short=50, clearance=10, width=1`，要求严格下降。每个加权项都是真实
违规，因此不会出现"用软收益换硬约束"。同时保留"规则同余丢失即拒绝"。

**算子最终形态**：`widen_narrow_tracks` 默认盲加宽（不做几何预检），
由 DRC + 加权事务门裁决；加宽失败时回滚字节级快照。

**直接测量（单板，事务门）**

| 板 | 修前 | 盲加宽 + 加权门 |
|---|---|---|
| 0006 | 2 width | **0** |
| 0057 | 5 width | **0** |
| 0023 | 2 width | **0**（矩形几何 + nudge） |
| 0029 / 0030 / 0037 / 0055 | 1–3 width | **0** |
| 0054 | 8 width + 1 open | 4 width（门拒绝剩余批次） |
