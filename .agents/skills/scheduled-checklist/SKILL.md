# scheduled-checklist: 层验证纪律与反自欺

## Why This Exists

用户纪律（多次校准后固化）："在没有彻底验证上一层有效或无效条件
下，不得考虑下一层是否有效，上一层没有验证结果后续都是空中楼阁。"
Agent4Sci 的 scheduled checklist 干预是实证最高杠杆之一。

## A-E 层验证清单（每次评估必走）

判定"没起作用"的原因在哪层，**逐层给验证证据**再进下层：

- **A 方向**：目标分解对不对？（验证: 历史收敛/负结果证据）
- **B 技术路线**：路线本身有没有正向实证？（验证: 路线下产出的实测 delta）
- **C 基础结构**：契约/实现缺陷？（验证: 六类契约断裂逐案前后对照）
- **D 性能机制**：改进回路在工作吗？（验证: 环产出的采纳/拒绝记录）
- **E 迭代时间**：已验证机制跑够了吗？（验证: A/B 轮次与跨板存活）

## 五问卡点分析（禁 yes/no 二值）

1. 是所有条件都 work/not work 吗？（极化边界在哪）
2. 什么条件下 work、什么条件下 not？
3. 关键因素是什么？
4. 该因素为什么决定成败？（机理，不是相关性）
5. 能否修改提升 work 范围？

## 反自欺核对表（汇报前逐条过）

- [ ] 数字来自实时测量还是快照？（stale pairs 案）
- [ ] 基线和处理组的口径一致吗？（consolidate 两态混用案）
- [ ] 增益有没有牺牲别的指标？（裸跑 -4 开 +3 短案）
- [ ] "通过"是固定评测器判的还是自己说的？
- [ ] 负结果记录了吗？（反例账是资产不是耻辱）
- [ ] 契约两端读的是同一个真理源吗？（规则表污染案）

## 反例（别这么干）

- 直接讨论 C 层方案而 A/B 层无验证 —— 空中楼阁。
- "进展良好"而无口径一致的前后数字。
- 把失败藏进脚注 —— 反例账必须显式。
