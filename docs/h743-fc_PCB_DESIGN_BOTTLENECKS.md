## 三、核心卡点

### 卡点 1：BGA 球场物理拥塞（根本限制）

**问题描述**：
TFBGA240 0.8mm 球场，265 球挤在 12.8mm × 12.8mm 区域。
逃逸通道容量有限——每通道仅容 1 根线。

**数学约束**：
```
球距 = 0.8mm
球半径 = 0.225mm
通道间隙 = 0.8 - 2×0.225 = 0.35mm
线宽 = 0.1mm, 间隙 = 0.09mm (JLC 极限)
单线占用 = 0.1 + 2×0.09 = 0.28mm
剩余空间 = 0.35 - 0.28 = 0.07mm → 不够第二根线
结论: 每通道仅容 1 根逃逸线
```

**物理限制**：
```
Dogbone via (0.4mm) 对角缝隙:
  对角中心距球心 = 0.566mm
  最小距离 = 0.225 + 0.2 + 0.09 = 0.515mm
  0.566 > 0.515 ✓ 可放
  但: 265 球 ≈ 256 缝隙, 42+ 网竞争 → 拥塞
```

**影响**：
- 42+ 网需逃逸 → 通道不足
- 逃逸线互相碰撞 → 短路
- GridModel 0.16mm 栅格无法精确表示 0.35mm 通道

**解决方向**：
1. 联合布线（MMCF 全局分配）— 已实现但碰撞仍存
2. 换更大封装（LQFP/0.8mm pitch）— 减少逃逸压力
3. 手工 KiCad 编辑 — 精确控制逃逸路径

---

### 卡点 2：GridModel 栅格精度不足

**问题描述**：
GridModel 使用 0.16mm 栅格离散化铜箔。但实际铜边界是连续的。
栅格无法精确表示 0.35mm 通道中的线间隙。

**量化**：
```
栅格 = 0.16mm
线宽 = 0.1mm (0.625 格)
间隙 = 0.09mm (0.56 格)
→ 栅格误差 ≈ 0.08mm (与间隙同量级!)
→ "看着不撞"实际撞
```

**影响**：
- 24% 走线有精确碰撞（1553/6388）
- 838 对 < 0.09mm（JLC 违规）
- 274 对负间隙（真短路）

**解决方向**：
1. 精确碰撞验证（geomir）— 已实现，短路 -89%
2. 更细栅格（0.08mm）— 4x 慢但更准
3. 连续空间求解器（非栅格）— 需要新算法

---

### 卡点 3：电源网多焊盘连接

**问题描述**：
GND 有 114 个焊盘，3V3 有 55 个。
三合一只连每网一对焊盘（球→连接器）。
剩余 48+ 对需单独连接。

**量化**：
```
GND: 114 pads → 24 对断线
3V3: 55 pads → 48 对断线
5V:  20 pads → 4 对断线
电源网总计: 82 对断线
```

**影响**：
- 电源网断线 → 电路不工作
- 补线直穿其他网 → 短路
- 需逐对路由（非直线）

**解决方向**：
1. 平面 via 连接 — 已实现（184 个 via）
2. 逐对 GPU 路由 — 已实现但碰撞率高
3. 铜皮灌注 + via 缝合 — 标准 PCB 做法

---

### 卡点 4：精确验证与速度的矛盾

**问题描述**：
精确碰撞验证（geomir 0.01mm）能防短路（-89%），但：
- 慢（675s/31 网，vs 79s 不验证）
- 跳过率高（28/35 网跳过）
- 跳过 → 断线

**量化**：
```
精确验证: 675s, 7/35 成功, 28/35 跳过
无验证:   79s, 31/42 成功, 0/42 跳过
→ 精确验证防短路但制造断线
```

**解决方向**：
1. GPU 加速验证 — 需要 geomir GPU 版
2. 两阶段路由 — 先宽松后精确
3. 接受少量短路 — JLC 可能容忍

## 四、已实现工具链

### fluxpcb/kicadgen/ 新增模块

| 模块 | 功能 | 性能 |
|------|------|------|
| `bga_dogbone.py` | BGA dogbone 逃逸 | 0.4mm via 对角缝隙 |
| `gpu_eikonal.py` | GPU Eikonal 路由器 | 25x 加速 (RTX 2060) |
| `triple_route.py` | MMCF+LLM+Eikonal 三合一 | 42 网/79s |
| 精确碰撞验证 | geomir 0.01mm | 短路 -89% |

### 核心算法

**Eikonal 光线追踪**（Fermat 原理）：
```
|∇T| = n(x)/c
T(x) = 到目的地的最小成本
路径 = -∇T (梯度下降)
```

**GPU FIM**（Fast Iterative Method）：
```
FMM(串行): 优先队列逐格 → 3s/网
FIM(并行): 全格同时更新 → 0.1s/网 (25x)
```

**MMCF 全局分配**（非交叉约束）：
```
min Σ cost(net_i, gap_j)
s.t. 非交叉约束
排序贪心: 按 x 排序 → 顺序分配
```

## 七、结论

**fluxpcb 工具链已完整**（Eikonal + MMCF + GPU + 精确验证），但 **TFBGA240 0.8mm 球场物理拥塞**是根本限制。

**完全可加工需要**：
1. 手工 KiCad 精修（短期可行）
2. 或换更大封装（减少逃逸压力）
3. 或连续空间求解器（长期研究）

**工具链可复用于其他板卡**（0.5mm pitch BGA、QFP 等）。
